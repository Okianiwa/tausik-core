# Автономный цикл (autoloop)

Прогон задач TAUSIK без человека рядом: супервизор снаружи запускает Claude Code
итерациями, каждая берёт одну задачу и доводит её до закрытия.

## Зачем он нужен

Одна сессия агента упирается в контекстное окно. Когда оно заполняется, качество
падает, а очистить его изнутри нельзя. Цикл превращает «одну длинную сессию» в
цепочку коротких: каждая начинается с чистого контекста и заканчивается закрытой
задачей плюс handoff для следующей.

## Ключевой принцип: процесс вместо /clear

`/clear` — команда TUI. Ни агент, ни хук вызвать её не могут. Поэтому очистка
контекста здесь достигается единственным доступным способом — **завершением
процесса**: супервизор (`autoloop_run.py`) поднимает на каждую итерацию новый
`claude -p`, а старый умирает вместе со всем своим контекстом.

Между итерациями переживает не разговор, а **состояние**: задачи, шаги плана,
логи и handoff лежат в `.tausik/tausik.db`. Следующая итерация читает их через
`/start` и продолжает с того же места. Отсюда правило: всё, что должно дожить до
следующей итерации, обязано попасть в БД (`task log`, handoff), а не остаться в
переписке.

## Как запустить

```bash
python .claude/scripts/autoloop_run.py run                     # прогон по очереди задач
python .claude/scripts/autoloop_run.py run --max-iterations 5  # ограничить прогон
python .claude/scripts/autoloop_run.py run --dry-run           # показать команду и выйти
python .claude/scripts/autoloop_run.py report                  # сводка прошлого прогона
```

Флаги: `--model` (модель для итераций), `--timeout` (секунд на итерацию, по
умолчанию 3600), `--max-idle`, `--max-crashes` — последние два перекрывают
конфиг.

Задачу супервизор выбирает сам: сначала `active` (чья-то незакрытая работа),
затем `planning`. Пустая очередь — цикл просто не стартует.

## Как остановить

```bash
touch .tausik/.autoloop.stop                    # мягкая остановка (bash)
New-Item .tausik/.autoloop.stop -Force          # то же в PowerShell
```

Файл проверяется **перед** следующей итерацией; текущая доигрывается до конца —
убивать агента посреди правки дороже, чем подождать минуту. Удалите файл, чтобы
запускаться снова.

Ctrl+C тоже работает; метка прогона `.tausik/.autoloop.run` снимается в `finally`,
так что следующая интерактивная сессия не примет себя за автономную.

## Схема одной итерации

```
супервизор                          процесс claude -p
    │
    ├─ выбрал задачу ──────────────► /start → task start → работа
    │                                     │
    │                                     ├─ Stop-хук sensor.py: измеряет
    │                                     │  заполнение окна → autoloop/<session>.json
    │                                     │
    │                                     └─ Stop-хук exit_guard.py: если
    │                                        порог пройден — блокирует конец
    │                                        хода и требует handoff + /end
    │                                            │
    ├─◄── процесс завершился ────────────────────┘
    ├─ записал итерацию в .tausik/autoloop-run.jsonl
    ├─ проверил тормоза (stop-файл, лимиты, простой, падения)
    └─ следующая итерация ──────────────────────► новый процесс, чистый контекст
```

Два порога у `exit_guard.py`, потому что «окно заполняется» и «окно кончается» —
разные ситуации:

- **soft (30%)** — только на шве: все шаги плана активной задачи закрыты. Ничего
  не написано наполовину, перезапуск ничего не стоит.
- **hard (75%)** — независимо от состояния задачи. Дописать handoff важнее, чем
  доделать работу на остатках окна.

Заполнение считается не по суммарному расходу токенов за сессию, а по размеру
промпта последнего запроса (`input + cache_creation + cache_read`) — именно он
упирается в окно.

## Настройки

Блок `autoloop` в `.tausik/config.json`. Отсутствующий или битый конфиг — не
ошибка: подставляются значения по умолчанию.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `context_window` | `1000000` | размер окна модели в токенах — база для процента |
| `soft_threshold` | `30` | % заполнения для выхода на шве (задача завершена) |
| `hard_threshold` | `75` | % заполнения для аварийного выхода в любом состоянии |
| `max_iterations` | `20` | предел итераций за прогон |
| `max_idle_iterations` | `3` | итераций подряд без изменения статусов задач |
| `max_crash_streak` | `2` | падений `claude` подряд до остановки |

Нулевое или отрицательное значение любого лимита поднимается до 1: лимит,
отключающий сам себя, — единственная настройка, превращающая цикл в неуправляемый
прогон.

## Файлы состояния

| Путь | Кто пишет | Зачем |
|---|---|---|
| `.tausik/autoloop/<session_id>.json` | `sensor.py`, `exit_guard.py` | заполнение окна, состояние задачи, запрошенный выход — **по файлу на сессию** |
| `.tausik/autoloop/profiles/settings.git-<mode>.json` | супервизор | права итерации для режимов `commit` и `off` — перегенерируются на каждом прогоне |
| `.tausik/.autoloop.run` | супервизор | метка прогона: без неё автономия не активна |
| `.tausik/.autoloop.stop` | человек | кнопка остановки |
| `.tausik/autoloop-run.jsonl` | супервизор | журнал: по записи на итерацию, читается `report` |

Запись в журнале, открытая и не закрытая, — это и есть след падения: следующий
прогон помечает такие итерации как `crashed`.

Каталог `.tausik/autoloop/` содержит **только замеры**: дашборд берёт оттуда
самый свежий JSON, а чистка удаляет оттуда файлы старше суток. Всё остальное,
что цикл кладёт себе, живёт в подкаталогах — иначе профиль, переписываемый в
начале каждого прогона, показывался бы как текущий замер и исчезал бы через
сутки вместе со старыми состояниями.

## Типичные ошибки

**`[SKIP]` вместо `[PASS]` в выводе `verify` — самая дорогая.** Гейт pytest
запускается только по файлам, привязанным к задаче. Если `relevant_files` пусты
или ни один из них не отображается в существующий тест, гейт возвращает *успех* с
пометкой SKIP — тесты не запускались вовсе. QG-2 при этом видит зелёный
результат и закрывает задачу: зелёный фиктивный, проверки не было.

Лечится до `verify`, а не после:

```bash
.tausik/tausik task update <slug> --relevant-files <исходники> <тесты>
.tausik/tausik verify --task <slug>     # ждём [PASS] и ненулевой Duration
```

Отображение исходника в тест — по имени файла: `scripts/foo.py` → `tests/test_foo.py`
и `tests/test_foo_*.py`. Если тест назван иначе, перечислите его в
`--relevant-files` явно — тестовый файл в списке берётся как есть.

**`TAUSIK_AUTONOMY=1` в интерактивном терминале ничего не включает.** Переменная,
забытая в оболочке, не должна превращать чужую сессию в самокоммитящуюся, поэтому
режим требует трёх условий сразу: переменная, метка прогона `.autoloop.run` от
супервизора и отсутствие TTY. Запускайте цикл через `autoloop_run.py`.

**`report` пуст.** Прогонов не было либо журнал стёрт — это состояние, а не сбой.

## Что автономия не ослабляет никогда

Автономный режим убирает ровно одно — подтверждение человеком git-операций
(и делает это штатным одноразовым билетом `tausik push-ok` с TTL 60 с, привязанным
к HEAD). Всё остальное остаётся в силе:

- **QG-0 и QG-2** — задаче по-прежнему нужны цель, критерии приёмки и свежий
  зелёный `verify`;
- **`secret_scan`, `scope_write_gate`, `task_gate`** — без изменений;
- **`bash_firewall`** — `git push --force` (и `-f`, и `--force-with-lease`),
  `git reset --hard`, `git clean -fd`, `rm -rf /` заблокированы;
- **deny-лист профиля автономии** — второй слой поверх firewall: дополнительно
  `git rebase`, любой `rm -rf`, `curl`/`wget` и правка самих файлов настроек;
- **`TAUSIK_SKIP_HOOKS`** — не «ускорение», а дисквалификация: с ним автономия не
  включается, а супервизор вычищает переменную из окружения итерации. Автономный
  агент с выключенными гейтами — это не режим, который здесь предусмотрен.

Права итерации перечислены поимённо в `.claude/settings.autonomy.json` и
передаются только дочернему процессу (`claude -p --settings`). Интерактивные
сессии этот файл не читают; всё, чего в списке нет, в headless-режиме просто не
выполнится.
