# /auto — автономный прогон

Цикл выполняет задачи из `tausik.db` без человека: каждая итерация — отдельный процесс `claude -p` с чистым контекстом. Подробности механизма — `.claude/scripts/autoloop/README.md`.

Вызывай, когда просят «поработай над задачами сам», «запусти цикл», «автономный прогон», «делай сам», «разгреби очередь»: `/auto` (весь список), `/auto 3` (три итерации), `/auto стоп`, `/auto статус`, `/auto отчёт`, `/auto <направление работы>`.

## Разбор аргумента

Смотри на `$ARGUMENTS` и выбирай ветку. Слова понимаются по-русски и по-английски.

| Аргумент | Ветка |
|---|---|
| пусто | **Запуск** по всей очереди |
| число (`3`, `10`) | **Запуск** с `--max-iterations <число>` |
| `стоп`, `stop`, `хватит` | **Остановка** |
| `отчёт`, `отчет`, `report`, `итоги` | **Отчёт** |
| `статус`, `status`, `watch`, `дашборд` | **Дашборд** |
| `окно`, `оверлей`, `overlay` | **Оверлей** |
| любой другой текст | **Запуск с направлением** (текст — направление работы) |

---

## Ветка: Остановка

```bash
touch .tausik/.autoloop.stop
```

Скажи, что цикл встанет **после текущей итерации** — убивать агента посреди правки дороже, чем подождать. Напомни удалить файл перед следующим запуском (`rm .tausik/.autoloop.stop`), иначе новый прогон сразу остановится.

## Ветка: Отчёт

```bash
python .claude/scripts/autoloop_run.py report
```

Покажи вывод как есть. Если написано «прогонов не было» — предложи `/auto`.

## Ветка: Дашборд

```bash
python .claude/scripts/autoloop_run.py watch
```

Живой экран с котиком, прогрессом и токенами; выход по `q`. Предупреди, что команду лучше запускать в отдельном окне терминала — она занимает его целиком.

## Ветка: Оверлей

```bash
python .claude/scripts/autoloop_run.py overlay
```

Запускай **в фоне** (`run_in_background: true`): окно живёт своей жизнью и переживает прогон, а команда не вернётся, пока человек его не закроет.

Плавающее окошко поверх всех окон — те же данные, что в дашборде, но терминал остаётся свободным. Перетаскивается мышью, позиция запоминается между запусками; закрывается по `Esc` или правой кнопкой.

Если в ответ пришло «tkinter недоступен» или «графическая среда недоступна» — это не поломка (ssh, headless): предложи `/auto статус`.

## Ветка: Запуск

### 1. Проверь, не идёт ли уже прогон

```bash
ls .tausik/.autoloop.run
```

Если метка есть — **не запускай второй цикл**. Сообщи, что прогон уже идёт, и предложи `/auto статус` либо `/auto стоп`. (Сам скрипт тоже откажется, но лучше объяснить это словами, чем показать отказ.)

### 2. Собери очередь

```bash
.tausik/tausik task list --status planning
.tausik/tausik task list --status active
```

**Очередь пуста** → не запускай пустой цикл. Скажи, что задач нет, и предложи `/plan`. На этом остановись.

**Задано направление** → сопоставь текст с задачами очереди:
- подходящие есть → возьми их, назови пользователю, какие именно;
- подходящих нет → заведи задачи через скилл `/plan` (goal + критерии приёмки с негативным сценарием — иначе QG-0 не пустит их в работу), затем продолжай;
- часть есть, часть нужно завести → сделай и то и другое.

Направление передаётся в промпт каждой итерации флагом `--direction`, чтобы агент помнил приоритет, а не только слаг задачи.

### 3. Спроси про git — один раз за запуск

Используй `AskUserQuestion` с тремя вариантами:

| Ответ | Флаг | Что значит |
|---|---|---|
| Коммитить и пушить | `--git-mode full` | закрытые задачи уезжают на удалённый репозиторий |
| Только коммитить | `--git-mode commit` | коммиты локальные, push недоступен |
| Не трогать git | `--git-mode off` | команды add/commit/push убраны из разрешений |

Запрет — не просьба в промпте: в режимах `commit` и `off` соответствующие команды физически отсутствуют в профиле разрешений дочернего процесса.

Если проект не под git (`git rev-parse HEAD` падает) — вопрос не задавай, бери `off` и скажи об этом.

### 4. Запусти в фоне

```bash
python .claude/scripts/autoloop_run.py run --git-mode <режим> [--max-iterations N] [--direction "<текст>"]
```

Запускай **в фоне** (`run_in_background: true`), чтобы сессия осталась отзывчивой.

### 5. Скажи, что дальше

Коротко: какие задачи в работе, какой режим git, и как смотреть за прогоном:

- `/auto статус` — живой дашборд;
- `/auto отчёт` — итоги;
- `/auto стоп` — остановить.

## Границы

- **Не запускай второй цикл поверх идущего.** Две очереди на один проект дерутся за одни задачи.
- **Не выставляй `TAUSIK_AUTONOMY` вручную.** Метку прогона ставит только supervisor; без неё автономия не включается, и это защита от переменной, забытой в оболочке.
- **Не предлагай `--dangerously-skip-permissions`.** Профиль разрешений — единственное, что стоит между ночным прогоном и `rm -rf`.
- Пороги контекста и лимиты итераций живут в `.tausik/config.json` → `autoloop`. Меняй их там, а не флагами на каждый запуск.

## Gotchas

- **Прогон и открытая сессия человека делят один лимит.** Итерации жгут те же 180 минут и ту же ёмкость вызовов, что и разговор; после долгого прогона `task start` начнёт отказывать, пока сессию не закроют.
- **Наблюдатель контекста — не часть прогона.** Он чистит окно интерактивного чата и включается флагом `autoloop.watch` в `.tausik/config.json`; в автономной итерации он молчит — там контекст обнуляется выходом из процесса.
- **Коммит без подтверждения работает только внутри прогона.** Метка `.tausik/.autoloop.run` плюс `TAUSIK_AUTONOMY=1` плюс отсутствие TTY; в обычном чате правило «спроси перед коммитом» остаётся.
- **`TAUSIK_SKIP_HOOKS` дисквалифицирует автономию.** Беспилотный агент с выключенными гейтами — не режим, который тут предлагается: цикл просто не стартует.
- **Профиль разрешений генерируется каждый запуск.** Правки в сгенерированном файле переживают ровно до следующей итерации; менять надо шаблон `settings.autonomy.json`.
