# /auto — автономный прогон

Прогон бывает двух видов. **Ветку задаёт слово в аргументе — и только оно**, по таблице ниже. Обстоятельства человека ветку не переключают: «меня не будет», «я ухожу спать», «разрешаю все коммиты» — это контекст работы, а не выбор режима.

**В чате (`/auto`)** — работа идёт в этом же разговоре: человек её видит, может вмешаться, дописать, остановить. Когда окно контекста заполняется, агенту приходит просьба довести текущую задачу до логического конца и остановиться; как только прогон встал, наблюдатель проводит `/checkpoint` → `/clear` → `/start` и возвращает чат к работе. Это путь по умолчанию.

**Агентами (`/auto агенты`)** — очередь разгребают отдельные процессы `claude -p`, каждый с чистым контекстом; чат при этом остаётся свободным. Включается **только** словом `агенты` / `agents` / `headless` в аргументе.

Подробности механизма — `.claude/scripts/autoloop/README.md`.

Вызывай, когда просят «поработай над задачами сам», «запусти цикл», «автономный прогон», «делай сам», «разгреби очередь»: `/auto` (весь список), `/auto 3` (три итерации), `/auto стоп`, `/auto статус`, `/auto отчёт`, `/auto почисти`, `/auto <направление работы>`.

## Разбор аргумента

Смотри на `$ARGUMENTS` и выбирай ветку. Слова понимаются по-русски и по-английски.

| Аргумент | Ветка |
|---|---|
| пусто | **Запуск в этом чате** по очереди задач |
| `стоп`, `stop`, `хватит` | **Остановка** |
| `статус`, `status` | **Статус прогона** |
| `отчёт`, `отчет`, `report`, `итоги` | **Отчёт** (отдельной командой) |
| `дашборд`, `watch` | **Дашборд** (отдельной командой) |
| `окно`, `оверлей`, `overlay` | **Оверлей** (отдельной командой) |
| `почисти`, `убери`, `уборка`, `clean` | **Уборка контекста сейчас** — не дожидаясь порога; прогон продолжается |
| `агенты`, `agents`, `headless` | **Запуск агентами** — очередь разгребают отдельные процессы, чат свободен |
| `меня не будет`, `я ухожу`, `пока сплю`, `работай сам` | **Запуск в этом чате** — обстоятельство, а не переключатель режима; текст идёт направлением работы |
| любой другой текст | **Запуск в этом чате с направлением** (текст — направление работы) |

Ветка «агентами» включается только словом из её строки таблицы. Человек, которому нужны агенты, называет их: слово короткое и стоит в подсказке. Сомневаешься — бери чат: из разговора видно, что происходит, и человека можно спросить; из агентного прогона нельзя ни того, ни другого, а очередь уже разбирается.

## Ветка: Остановка

```bash
python .claude/scripts/autoloop_command.py stop
```

Команда останавливает тот режим, который идёт, и говорит какой.

В чате прогон снимается сразу: наблюдатель уходит в пределах секунды, в том числе посреди начатой уборки. Работа, которая уже идёт, **не обрывается** — просто следующего круга не будет.

У агентов останавливать нечего мгновенно: супервизор владеет процессами, поэтому его просят закончить текущую итерацию и не начинать следующую.

## Ветка: Статус прогона

```bash
python .claude/scripts/autoloop_command.py status
```

Покажи ответ как есть: он называет, какой режим идёт — в чате (с направлением и состоянием наблюдателя) или агентами.

## Ветка: Отчёт

```bash
python .claude/scripts/autoloop_run.py report
```

Покажи вывод как есть. Если написано «прогонов не было» — предложи `/auto`.

## Ветка: Дашборд

```bash
python .claude/scripts/autoloop_run.py watch
```

Живой экран с котиком, прогрессом и токенами; выход по `q`. Предупреди, что команду лучше запускать в отдельном окне терминала — она занимает его целиком.

## Ветка: Оверлей

```bash
python .claude/scripts/autoloop_run.py overlay
```

Запускай **в фоне** (`run_in_background: true`): окно живёт своей жизнью и переживает прогон, а команда не вернётся, пока человек его не закроет.

Плавающее окошко поверх всех окон — те же данные, что в дашборде, но терминал остаётся свободным. Перетаскивается мышью, позиция запоминается между запусками; закрывается по `Esc` или правой кнопкой.

Если в ответ пришло «tkinter недоступен» или «графическая среда недоступна» — это не поломка (ssh, headless): предложи `/auto статус`.

## Ветка: Уборка контекста сейчас

```bash
python .claude/scripts/autoloop_command.py clean
```

Покажи ответ как есть и **больше ничего не делай**: `/checkpoint` и `/clear` проведёт наблюдатель, а не ты. Своя попытка почистить контекст руками поверх запроса даст две уборки подряд.

Сам по себе наблюдатель ждёт три условия — заполненное окно, 45 секунд тишины и конец десятиминутного карантина после отказа. Просьба человека снимает все три сразу: он смотрит на окно и уже решил.

Чего просьба **не** снимает — идущую фоновую работу. Пока агент занят, уборка ждёт: `/clear` посреди работы теряет незавершённое, а человек, который просит чистку, может не знать, что агент в середине шага.

Прогона нет — команда откажет и запроса не оставит: наблюдатель живёт только внутри объявленного прогона, а забытый файл сработал бы внезапно на следующем `/auto`. В этом случае предложи `/auto`.

## Ветка: Запуск в этом чате

Этот путь — основной. Чат остаётся обычным, человек его видит и может вмешаться в любой момент; наблюдатель работает рядом и чистит контекст, когда тот заполняется.

### 1. Проверь, не объявлен ли прогон

```bash
python .claude/scripts/autoloop_command.py status
```

Если прогон уже идёт — не объявляй второй. Скажи, с каким направлением он идёт, и предложи `/auto стоп`.

### 2. Собери очередь и уточни направление

```bash
.tausik/tausik task list --status planning
.tausik/tausik task list --status active
```

**Очередь пуста и направления нет** → не объявляй прогон в пустоту. Предложи `/plan`.

**Задано направление** → сопоставь с очередью: подходящие задачи назови; которых нет — заведи через `/plan` (goal + критерии приёмки с негативным сценарием, иначе QG-0 не пустит их в работу).

Если для работы нужны уточнения — **задай их сейчас**, пока человек рядом. После объявления прогона он может уйти.

### 3. Объяви прогон

```bash
python .claude/scripts/autoloop_command.py start "<направление>"
```

Без аргумента направлением станет очередь задач TAUSIK. Команда пишет признак прогона и поднимает наблюдателя — перезапуск сессии не нужен.

### 4. Скажи, что дальше, и берись за работу

Коротко: над чем работаешь, что чистка контекста произойдёт сама, и что остановить — `/auto стоп`. После этого начинай работать над задачей, не дожидаясь ничего.

Если после конца хода прошло 20 минут и ничего не началось, наблюдатель подаст ту же строку продолжения без уборки — прогон, вставший между шагами, ждёт человека, которого нет. «Конец хода» берётся у хоста (флаг хука `Stop`), а не по тишине транскрипта: при длинной команде транскрипт стоит минутами, и по нему идущий ход неотличим от вставшего прогона. Три подачи, ни одна из которых ничего не родила, означают не «встал», а «кончилось»: механизм пишет об этом в лог и до конца прогона чат больше не трогает.

Когда окно заполнится, в конце очередного хода придёт просьба свернуть текущую задачу и не начинать новой; когда прогон встанет, наблюдатель проведёт `/checkpoint` → `/clear` → `/start` и последним шагом вернёт чат к работе строкой «Продолжай прогон. Направление: …». Эта строка придёт как обычное сообщение человека — работай по ней так же, как работал бы по его просьбе: возьми следующий шаг и делай. Всё, что должно пережить очистку, к этому моменту обязано лежать в БД (`task log`, handoff), а не в переписке.

## Ветка: Запуск агентами

Очередь разгребают отдельные процессы `claude -p`, каждый с чистым контекстом. Чат при этом свободен — человек может им пользоваться или закрыть.

Оба режима берут работу из одной очереди, поэтому одновременно не запускаются: `autoloop_run.py` откажется стартовать поверх объявленного прогона в чате, а `/auto` откажется объявлять прогон поверх идущих агентов. Это физический отказ в коде, а не просьба в тексте.

### 1. Проверь, не идёт ли уже прогон

```bash
ls .tausik/.autoloop.run
```

Если метка есть — **не запускай второй цикл**. Сообщи, что прогон уже идёт, и предложи `/auto статус` либо `/auto стоп`. (Сам скрипт тоже откажется, но лучше объяснить это словами, чем показать отказ.)

### 2. Собери очередь

```bash
.tausik/tausik task list --status planning
.tausik/tausik task list --status active
```

**Очередь пуста** → не запускай пустой цикл. Скажи, что задач нет, и предложи `/plan`. На этом остановись.

**Задано направление** → сопоставь текст с задачами очереди:
- подходящие есть → возьми их, назови пользователю, какие именно;
- подходящих нет → заведи задачи через скилл `/plan` (goal + критерии приёмки с негативным сценарием — иначе QG-0 не пустит их в работу), затем продолжай;
- часть есть, часть нужно завести → сделай и то и другое.

Направление передаётся в промпт каждой итерации флагом `--direction`, чтобы агент помнил приоритет, а не только слаг задачи.

### 3. Спроси про git — один раз за запуск

Используй `AskUserQuestion` с тремя вариантами:

| Ответ | Флаг | Что значит |
|---|---|---|
| Коммитить и пушить | `--git-mode full` | закрытые задачи уезжают на удалённый репозиторий |
| Только коммитить | `--git-mode commit` | коммиты локальные, push недоступен |
| Не трогать git | `--git-mode off` | команды add/commit/push убраны из разрешений |

Запрет — не просьба в промпте: в режимах `commit` и `off` соответствующие команды физически отсутствуют в профиле разрешений дочернего процесса.

Если проект не под git (`git rev-parse HEAD` падает) — вопрос не задавай, бери `off` и скажи об этом.

### 4. Запусти в фоне

```bash
python .claude/scripts/autoloop_run.py run --git-mode <режим> [--max-iterations N] [--direction "<текст>"]
```

Запускай **в фоне** (`run_in_background: true`), чтобы сессия осталась отзывчивой.

### 5. Скажи, что дальше

Коротко: какие задачи в работе, какой режим git, и как смотреть за прогоном:

- `/auto статус` — живой дашборд;
- `/auto отчёт` — итоги;
- `/auto стоп` — остановить.

## Границы

- **Не запускай второй цикл поверх идущего.** Две очереди на один проект дерутся за одни задачи.
- **Не выставляй `TAUSIK_AUTONOMY` вручную.** Метку прогона ставит только supervisor; без неё автономия не включается, и это защита от переменной, забытой в оболочке.
- **Не предлагай `--dangerously-skip-permissions`.** Профиль разрешений — единственное, что стоит между ночным прогоном и `rm -rf`.
- Пороги контекста, интервал якоря и лимиты итераций живут в `.tausik/config.json` → `autoloop`. Меняй их там, а не флагами на каждый запуск. Умолчания: `soft_threshold` 50 (на нём просят свернуться), `hard_threshold` 75, `anchor_seconds` 600.

## Gotchas

- **Прогон и открытая сессия человека делят один лимит.** Итерации жгут те же 180 минут и ту же ёмкость вызовов, что и разговор; после долгого прогона `task start` начнёт отказывать, пока сессию не закроют.
- **Просьба свернуться приходит от Stop-хука, уборка — от наблюдателя.** Хук достаёт агента в конце каждого хода, поэтому просьба доходит и посреди сплошной работы; наблюдатель ждёт, пока прогон реально встанет (флаг Stop-хука, а не тишина транскрипта), и только тогда вытирает окно. Уборка посреди длинного вызова инструмента поэтому невозможна.
- **Вставший прогон пинают каждые десять минут, а не сразу.** Якорь бьёт только по чату, у которого ход закончен (флаг Stop-хука), фоновой работы нет и уборка не взведена; три безрезультатных подачи подряд — и он замолкает. Текст подачи прямо разрешает решить заданный вопрос самому: отвечать некому.
- **Наблюдатель живёт ровно столько, сколько объявленный прогон.** Признак — файл `.tausik/.chat-loop.json`, который пишет `autoloop_command.py start` и убирает `stop`. Вне прогона механизма нет вообще: наблюдатель не поднимается, замер контекста не пишется, чат обычный. Флаг `autoloop.watch` в конфиге больше ничего не включает.
- **Коммит без подтверждения работает только внутри прогона.** Метка `.tausik/.autoloop.run` плюс `TAUSIK_AUTONOMY=1` плюс отсутствие TTY; в обычном чате правило «спроси перед коммитом» остаётся.
- **`TAUSIK_SKIP_HOOKS` дисквалифицирует автономию.** Беспилотный агент с выключенными гейтами — не режим, который тут предлагается: цикл просто не стартует.
- **Якорь не стирает черновик, но и не обходит его.** Подача идёт путём шага продолжения — без `Esc`, потому что `Esc` перед этим шагом прерывает ход, который ещё дорисовывается (выведено замером). Плата за это названа прямо: недописанная строка, пролежавшая в чате 20 минут, склеится с подачей и уедет одним сообщением. Уборка так не влипает — она жмёт `Esc` перед каждой командой и сверяет экран.
- **Сердцебиение оснастки не считается работой агента.** MCP-серверы просыпаются по расписанию — индексатор графа в `D:/asynchronus` делал это каждые 54 с и держал уборку заблокированной весь вечер, потому что 41 с тишины между всплесками не дотягивала до нужных 45 с. Работой считается то, что родилось, пока транскрипт ещё писался: настоящий ход всегда пишет в него после запуска процесса. Плашка при этом называет процесс, которого ждёт, а не только их количество.
- **Профиль разрешений генерируется каждый запуск.** Правки в сгенерированном файле переживают ровно до следующей итерации; менять надо шаблон `settings.autonomy.json`.
