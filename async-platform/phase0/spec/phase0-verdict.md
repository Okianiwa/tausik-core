# Phase 0 — Вердикт: ECS + deferred writes

Дата прогона: сессия #1. Железо: Ryzen 7800X3D (8 физ. ядер / 16 потоков, 96 МБ L3), JDK 21.
Прототип: `../prototype` (throwaway). Сцена: N=150 000 «машин» в одной плотной точке, 5 систем,
2 стадии. WORK=24 (компьют-представительная мешалка), warmup=10, measure=30, медиана тика.

## Результаты (2 прогона)

| Threads | Run 1 tick | Run 1 ×ref | Run 2 tick | Run 2 ×ref |
|--:|--:|--:|--:|--:|
| reference (no-pool) | 18.96 ms | 1.00× | 21.47 ms | 1.00× |
| @1 | 18.95 ms | 1.00× | 18.80 ms | 1.14× |
| @2 | 11.04 ms | 1.72× | 21.40 ms | 1.00× ⚠ выброс |
| @4 | 5.23 ms | **3.62×** | 5.40 ms | **3.98×** |
| @8 | 3.22 ms | **5.90×** | 3.39 ms | **6.34×** |
| @16 | 5.74 ms | 3.31× ⚠ | 7.11 ms | 3.02× ⚠ |

**Пик ≈ 6× на 8 физических ядрах** (74–79% от идеального 8×). Серийная доля по Амдалу
(из S@8 vs @1): **~5–6%** (apply-фаза + накладные пула) → теоретический потолок ~16–20×,
на практике ограничен 8 физ. ядрами и пропускной способностью L3.

### Детерминизм
`checksum(reference) == checksum(parallel@8)` = `4682464077098334646`, **бит-в-бит идентично
и воспроизводимо между прогонами**. Прямые записи идут в disjoint-колонки (гонок нет by
construction), отложенные — в упорядоченной apply-фазе (сортировка буферов по
`(systemOrder, chunkStart)` не зависит от порядка завершения потоков).

### Негативные / граничные (все passed)
- **write-write конфликт** (два писателя ENERGY) → планировщик разнёс по 2 стадиям (сериализация). ✓
- **OP_SET резолюция** → поздний systemOrder побеждает, 200/200 стабильно на 8 потоках. ✓
- **Контракт** → запись необъявленного компонента бросает `ContractViolation` (не проглочено). ✓
- **Границы** → N=0, pure-read система (writes=0), пустой command-buffer — без падений. ✓

|---|---|---|---|

## Находки для платформы

1. **Пул размерять по ФИЗИЧЕСКИМ ядрам, не по `availableProcessors()`.** @16 (SMT) стабильно
   *хуже* @8 (3× против 6×): переподписка 8 ядер, contention за execution units + L3-bandwidth.
   Рабочий сет L3-резидентен (X3D) → на высоких thread-count упираемся в пропускную способность,
   а не в компьют. (memory #1, gotcha записан.)
2. **Локальность SoA работает** — колоночная раскладка держит горячие компоненты в L3; это прямой
   плюс на 7800X3D и подтверждает ставку из ADR #1.
3. **Валидация контракта фактически бесплатна** — «доверяй объявлениям» жизнеспособно.

## Честные ограничения (что НЕ доказано)

- Это **той-модель**: фикс. набор компонентов, целочисленная мешалка вместо реальной игровой
  логики MC, чистые непересекающиеся write-множества.
- Бенч ручной (warmup+медиана), не JMH; на низких thread-count заметна вариативность (@2 дал
  выброс). Прод-замеры → JMH.
- **Главный непокрытый риск:** доказан МЕХАНИЗМ (планировщик + deferred + детерминизм + масштаб),
  но НЕ доказано, что реальная логика MC раскладывается в **низкоконфликтные** системы. У настоящих
  подсистем (редстоун, взаимодействие сущностей) read/write-множества грязнее → больше конфликтов →
  меньше систем на стадию → меньше реального speedup, чем на чистой игрушке. Игрушка — это
  верхняя граница, не прогноз.

## Вердикт: **GO** на модель ECS + deferred writes

Три kill-критерия пройдены с запасом. Механизм сильный, детерминированный, дешёвый в валидации.

**Следующая story `core-rewrite`** должна снять главный непокрытый риск — начать с самой
независимой подсистемы (**тик блок-энтити**: печи/хопперы/машины — очевидные компоненты,
локальные read/write), измерить реальную конфликтность на настоящей логике, и только потом
двигаться к грязным подсистемам (сущности → блок-апдейты/редстоун). Декомпозиция реальных
подсистем в низкоконфликтные системы — и есть настоящая работа ядра.
